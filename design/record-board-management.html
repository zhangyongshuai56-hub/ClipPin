②记录重命名与编辑内容

编辑内容：仅对文本类（文本 / 代码 / 链接 / 其他）开放，图片与文件不可编辑。保存后重算内容指纹并重新分类； 若编辑后的内容与库中已有记录完全相同，自动合并（保留已有记录并刷新其时间），提示「已与已有记录合并」。
交互入口：右键菜单（⌘E 编辑 / ⌘R 重命名）与两个模态

技术方案摘要

层面变更
DB 迁移 v4 removed_from_history INTEGER NOT NULL DEFAULT 0（软删除标记）、 title_is_custom INTEGER NOT NULL DEFAULT 0（命名标记），追加式迁移，老库自动升级
Rust Core 新增 API remove_item_from_history(id) → RemovedOutcome { deleted | kept_in_board }（按收藏状态自动选择软/硬删）
edit_text_item(id, new_text) → EditOutcome { item, merged }（重算哈希 / 重分类 / 冲突自动合并）
rename_item(id, title) · rename_board(id, name)
查询规则 默认「剪贴板」视图与全局搜索追加 removed_from_history = 0 过滤；文件夹视图不过滤；
移出文件夹时若为软删除状态 → 物理删除；编辑后内容自动重跑 URL / 代码分类与语言识别
Swift / UI 右键菜单按视图与收藏状态切换「删除 / 从剪贴板移除」；重命名与编辑各一个 Sheet（⌘R / ⌘E）；
chip 右键「重命名…」；软删除 toast 反馈；编辑合并时 toast 提示
不变化收藏豁免自动清理 / 历史上限的既有语义；图片 / 文件类记录不可编辑；去重、搜索索引机制

待确认的决策点

请确认以下 4 点（可直接回复编号 + 意见）

  1. 删除语义：在「剪贴板」删除已收藏条目 = 软删除（历史移除、收藏保留）；在文件夹视图内删除 = 真删除。（推荐）是否认可？
  2. 编辑冲突：编辑后的内容与已有记录完全相同时自动合并为一条，而不是报错阻止。（推荐）是否认可？
  3. 命名记录是否豁免自动清理与历史上限？方案默认不豁免（保持现有清理语义）；如希望命名即永久保留，请说明。
  4. 编辑入口限制在文本类记录（文本 / 代码 / 链接 / 其他）；图片与文件暂不支持编辑。（推荐）是否认可？
